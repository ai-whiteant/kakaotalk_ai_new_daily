# 1. 프로젝트 목적

`Kakao ai news`는 단순 뉴스 검색기가 아니라 국내외 AI 동향을 정기적으로 탐색하고,
중복·저품질 정보를 제거한 뒤 중요 뉴스를 선별하여 사용자가 빠르게 이해할 수 있는
AI 뉴스 브리핑을 생성하고 KakaoTalk으로 전달하는 시스템이다.

특히 AI 교육, 생성형 AI, 기술·모델, 정책·윤리, 산업, 국내 AI 생태계,
AI 보안 분야를 지속적으로 관찰한다.

최종 결과는 단순 기사 요약을 넘어 다음 질문에 답해야 한다.

1. 무엇이 발생했는가?
2. 왜 중요한가?
3. 교육·사회·산업에 어떤 영향을 줄 수 있는가?
4. 교사와 학생이 알아야 할 부분은 무엇인가?
5. 원문에서 무엇을 추가 확인할 수 있는가?

# 2. 시스템 기본 구조

전체 파이프라인은 다음 역할을 명확하게 분리한다.

Tavily
→ 뉴스 탐색·원문 후보 확보
→ 날짜 및 URL 확보

Gemini API
→ 기사 분류
→ 중복 제거 보조
→ 중요도 평가
→ 핵심 내용 요약
→ 시사점 분석
→ 교육 활용 아이디어 생성
→ 최종 브리핑 구성

Kakao API
→ 최종 브리핑 전달
→ KakaoTalk `나에게 보내기`

각 단계의 오류를 분리하여 한 서비스의 장애가 전체 프로젝트 오류로 오인되지 않도록 한다.

# 5. 검색 전략

단일 검색어 하나로 모든 뉴스를 검색하지 않는다.
분야별로 복수 검색 쿼리를 사용하고 결과를 통합한다.

- 정책: AI regulation, AI copyright, AI privacy, AI education policy

검색어는 최신 AI 용어와 주요 사건에 따라 지속적으로 보완할 수 있다.

# 6. 출처 품질 관리

우선순위:
1. 정부·공공기관, 대학·연구기관, 공식 기업 발표, 공식 기술 문서
2. 국제·국내 주요 언론, 전문 기술·과학 매체
3. 전문 분석기관, 검증 가능한 업계 전문 매체

출처가 불분명한 글, 복제 기사, 과장성 콘텐츠, 광고성 콘텐츠, 날짜 확인이 어려운 콘텐츠,
사실과 의견 구분이 어려운 콘텐츠는 낮게 평가하거나 제외한다.

기본 원칙은 `신뢰 출처 우선 + 전체 뉴스 탐색 + 저품질 출처 제외`이다.

# 7. 중복 기사 처리

같은 사건을 여러 언론사가 보도했을 경우 기사 개수로 중요도를 부풀리지 않는다.
사건, 인물·기관, 발표 내용, 날짜, 핵심 사실, URL, 제목 의미를 비교한다.
동일 사건이면 대표 기사 1건을 중심으로 통합하고, 필요한 경우 복수 출처로 교차검증한다.

# 9. 사실 검증 원칙

요약 전에 기사 발행일, 사건 발생일, 기관·기업명, 제품·모델명, 핵심 수치,
공식 발표 여부, 원문 URL을 확인한다.

중대한 주장이나 수치는 가능하면 복수 출처 또는 공식 1차 자료로 확인한다.
기사 제목만 보고 내용을 추론하지 않는다.
확인되지 않은 전망·루머·추측을 사실처럼 작성하지 않는다.

# 10. AI 요약 작성 규칙

Gemini는 원문의 의미를 유지하면서 간결하게 재구성한다.

금지:
- 원문에 없는 사실 생성
- 과도한 전망
- 과장된 제목
- 정치적·상업적 편향
- 출처 없는 수치 생성
- 링크 생성 또는 추측
- 사실과 의견 혼합

기본 구조:
제목 → 핵심 내용 → 중요성 → 교육적 시사점 → 필요 시 수업 활용 → 원문 링크

---

# 11. 교육적 시사점

교육 관련 기사에는 교사의 역할 변화, 학생 AI 활용 역량, AI 리터러시,
직업교육 변화, 평가 방식 변화, 개인정보·저작권, AI 윤리, 수업 활용 가능성을 검토한다.

교육적 연관성이 약한 산업 뉴스에는 억지로 교육적 의미를 부여하지 않는다.

# 13. 기사 수와 메시지 가독성

기본 최종 기사 수는 8~12건을 권장한다.
기사 수를 맞추기 위해 중요도가 낮은 기사를 억지로 포함하지 않는다.
중대한 뉴스가 적으면 기사 수를 줄이고, 품질을 기사 수보다 우선한다.

KakaoTalk 메시지는 모바일 가독성을 최우선으로 하며 긴 문단, 반복, 불필요한 설명을 피한다.
메시지 길이 또는 템플릿 제한을 초과하면 AI 교육 / 기술·산업 / 정책·주간 요약 등
논리적인 단위로 분할한다.

---

# 14. API 역할 분리 및 장애 격리

- Tavily API/MCP: 뉴스 탐색
- Gemini API: 분석·평가·요약·브리핑 생성
- Kakao API: 메시지 전달

하나의 API가 실패했다고 다른 API 설정까지 임의로 변경하지 않는다.
오류 발생 시 장애 지점을 먼저 식별한다.

상태 표시는 필요에 따라 PASS / WARN / HOLD / FAIL을 사용한다.

---

# 15. Gemini Free/Paid 환경 정책

Paid Tier와 Free Tier를 별도 실행 환경으로 취급한다.
이미 검증된 Paid 환경의 설정을 Free Tier 문제 해결을 위해 임의로 변경하지 않는다.

Free Tier 오류 시 API Key 인증, 프로젝트 접근 권한, Free Tier eligibility,
모델별 사용 가능 여부, Rate Limit, Billing 상태, Google 측 프로젝트 제한을 구분한다.
Free Tier 장애를 Tavily 또는 Kakao 오류로 확대 해석하지 않는다.

# 16. 보안

Tavily API Key, Gemini API Key, Kakao Access Token, Client Secret,
Refresh Token 등 인증정보는 코드·문서·Git 저장소·보고서·Kakao 메시지에 노출하지 않는다.

민감한 설정 파일은 `.gitignore` 대상으로 관리한다.
오류 보고 시 인증정보는 반드시 마스킹한다.

# 19. 프로젝트 핵심 원칙

이 프로젝트에서 가장 중요한 것은 `많은 뉴스를 보내는 것`이 아니라
`읽을 가치가 있는 뉴스를 정확하게 보내는 것`이다.

우선순위:
최신성 + 사실성 + 출처 신뢰성 + 중요도 + 교육적 활용성 + 모바일 가독성 + 보안성

최종 목표:

> 최근 AI 변화를 짧은 시간 안에 정확하게 파악하고,
> 교육과 실제 업무에 활용할 수 있는 신뢰도 높은 개인 AI 뉴스 브리핑 시스템.
