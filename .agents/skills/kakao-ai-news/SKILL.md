# Kakao ai news

## 실행 범위와 연결

- 표시 이름은 **Kakao ai news**, 호출 식별자는 `$kakao-ai-news`이다.
- 스킬 실행 요청에 뉴스 전송이 포함되어 있으면 완성 후 본인에게 전송한다. 미리보기·검색만 요청했다면 전송하지 않는다. 스킬 생성·수정 자체는 실행 요청이 아니다. 정기 실행은 별도 요청 없이는 등록하지 않는다.
- 사용 가능한 도구에서 Tavily Remote MCP 검색·추출 도구와 카카오 나에게 보내기 도구를 탐색하고 실제 스키마를 확인한다. 도구 이름을 가정하지 않는다.
- Tavily Remote MCP가 없으면 연결이 필요하다고 알린다. 다른 검색 엔진을 Tavily 사용으로 표현하지 않는다. 공식 연결 주소와 인증 안내는 [Tavily MCP 문서](https://docs.tavily.com/documentation/mcp)를 참고한다. API 키를 스킬, 결과물, 로그에 저장하지 않는다.
- 카카오 연결만 없으면 검색과 전송용 원고를 먼저 완성하고 미전송 상태 및 필요한 연결을 알린다. 사용 가능한 인증된 카카오 도구를 우선 사용하고, REST API를 사용할 경우 [카카오 연결 및 전송](references/kakao.md)을 읽는다.

## 검색과 선정

1. 실행 시각을 Asia/Seoul 기준으로 구하고 최근 7일 구간(현재 시각에서 7일 전부터 현재까지)을 명시한다. 날짜만 있는 기사는 날짜 단위로 판정하며 경계일의 시각 불명확성을 표시한다.
2. 한국어와 영어 검색을 각각 수행한다. 예: `AI 교육 학교 교사 정책 발표`, `인공지능 교육 대학 AI 리터러시`, `AI education schools teachers policy announcement`, `AI literacy university learning research`. 해외는 한 국가에만 집중하지 않는다.
3. 실제 도구가 지원하면 `time_range: week`, `topic: news`, `search_depth: advanced`를 사용한다. 필요하면 날짜 범위를 추가한다. 기관 발표·연구 누락을 보완할 때 `topic: general`로 추가 검색한다. 지원하지 않는 인수는 보내지 않는다.
4. 후보 원문을 Tavily 추출 도구로 확인한다. 검색 필터는 수정일 기준 결과도 포함할 수 있으므로 최초 발표·발행일을 원문에서 검증한다. 오래된 기사의 단순 갱신·재전재, 기간 밖 기사, 날짜를 확인할 수 없는 기사는 최종 목록에서 제외한다. 사건 발생일과 기사 발행일을 혼동하지 않는다.
5. 교육 현장의 AI 활용, AI 자체 교육·리터러시, 교원 역량, 교육 정책, 학습 성과·평가 연구를 다룬다. 교육과 직접 관계없는 모델 출시·투자 소식, 광고성 강좌 홍보는 제외한다.
6. 교육 현장 영향, 정책 적용 범위, 연구 근거, 새로움을 기준으로 기본 6건 안팎(최대 8건)을 선정한다. 국내·해외를 각각 2건 이상 확보하도록 검색하되 적합한 기사가 부족하면 수를 줄이고 부족 사실을 밝힌다. 같은 사건의 중복 보도는 하나로 통합한다.
7. 정부·교육기관·연구 원문과 신뢰할 수 있는 언론을 우선한다. 보도자료의 주장과 독립 검증을 구분하고 수치·인용은 확인된 내용만 쓴다. 추출에 실패하면 다른 원문을 찾고 검색 요약만으로 상세 사실을 만들어내지 않는다.

## 원고 형식

전체를 한국어로 작성하고 국내, 해외 순으로 묶는다. 외국어 제목은 의미를 보존해 번역한다. 각 기사에는 다음 필드를 모두 포함한다.

```text
AI 교육 주간 뉴스 | {조회 구간, KST}

[국내 또는 해외 · 번호]
제목: {기사 제목}
출처·발행일: {매체 또는 기관} | {YYYY-MM-DD}
핵심내용: {무엇이 발표되었고 누구에게 어떤 변화가 생기는지 1~2문장}
시사점: {교사·학교·학습자·교육정책에 대한 구체적인 의미 1문장}
링크: {검증된 원문 URL}
```

시사점은 기사 사실과 구분되는 분석으로 쓴다. 입증되지 않은 효과를 단정하지 않는다. URL은 검색 결과 주소가 아닌 실제 기사 주소를 사용한다.

## 전송과 결과 보고

- 모든 원고를 완성한 뒤 본인 수신 대상, 제목·핵심내용·시사점·링크 포함 여부, 날짜, 중복, 도구의 메시지 길이 제한을 확인한다.
- 본인에게만 전송한다. 친구·그룹·채널 발송 도구를 대체 사용하지 않는다. 이미 전송까지 요청받았다면 재확인을 요구하지 않는다.
- 길면 기사별 또는 연속된 번호가 있는 메시지로 나누되 필수 내용을 삭제하거나 URL을 잘라내지 않는다. REST 텍스트 템플릿의 제한과 링크 조건은 참조 문서를 따른다.
- 각 메시지의 성공 응답을 기록한다. 성공한 메시지를 다시 보내지 않는다. 타임아웃처럼 성공 여부가 불명확하면 자동 재전송을 중지하고 해당 번호를 알린다. 명확한 실패는 원인을 수정한 뒤 실패분만 한 번 재시도한다.
- 최종 응답에는 검색 구간, 국내·해외 기사 수, 전송 성공 메시지 수 또는 미전송 사유를 짧게 밝힌다. 연결·인증이 없거나 응답을 확인하지 못했으면 전송 완료라고 말하지 않는다.
